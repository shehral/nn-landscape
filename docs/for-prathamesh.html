Patterns this build

  • Independently-built document-parsing eval harnesses are omitting OCR-3 from their comparison sets. Both handwriting-ocr-llm-eval (this build) and velrim-eval (prior build) benchmark 4-5 engines — LlamaParse, Mistral OCR, Reducto, Gemini — without including OCR-3. The IDP Leaderboard ranking does not automatically generate practitioner-visible coverage in open eval tooling.
  • MCP servers are becoming a distribution layer for frontier vision APIs in document workflows. deepseek-vision-mcp wraps a multimodal vision model as an MCP server, reducing the cost of routing document images through a vision model in an agentic pipeline. This pattern — commoditizing access to frontier vision without a dedicated document-extraction API — applies competitive pressure to the make-vs-buy decision for OCR-3.
  • General-purpose VLM testing harnesses (vlm-testing, handwriting-ocr-llm-eval) are covering OCR and document extraction as secondary tasks alongside visual QA and chart understanding, rather than treating document extraction as a primary evaluation domain. This signals that practitioners may be treating OCR-as-a-feature as increasingly table stakes within general VLM capability assessments.
