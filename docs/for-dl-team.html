Patterns this build

  • Developers are treating OCR+VLM as a combined default architecture, not a choice between them. Three items this build (doc-extraction-ocr-vs-vlm, liteparse, document-extractor) all expose or benchmark combined OCR+VLM extraction stacks rather than either approach alone.
  • Open-weight OCR backends (Docling, PaddleOCR) are appearing as defaults in production doc AI platforms, routing around cloud OCR APIs. Two items (agentic-doc-intelligence-platform, ingestlib) both default to Docling or PaddleOCR for extraction without evaluating cloud alternatives.
  • Community-built evaluation benchmarks for VLM hallucination and extraction accuracy are proliferating alongside lab-published ones. Both vlm-groundbench and doc-extraction-ocr-vs-vlm are practitioner-authored reproducibility-focused evaluation tools, not institutional papers.
  • Agentic pipeline infrastructure is standardizing at high adoption rates (35K+ combined stars for cocoindex + promptfoo) independently of the OCR extraction layer, suggesting the integration surface below document processing APIs is maturing faster than the APIs themselves.
