Patterns this build

  • GRPO fine-tuning for document VLMs is becoming standard infrastructure: ms-swift (15K stars), NeMo Automodel (833 stars), and verl-omni (794 stars) all added native GRPO support for Qwen3-VL and GLM this week. FireRed-OCR-2B demonstrated this paradigm eliminates structural hallucinations in tables; commodity access to the technique means competitor GRPO-tuned OCR variants are likely to appear on the IDP Leaderboard within months.
  • Independent third-party PDF parser benchmarks are multiplying, with Nanonets not confirmed as a participant: opendataloader-pdf (28K stars), ParseBench (CVPR 2026), pdfmux's self-auditing benchmark, and Documents-Parsing-Lab all ran external comparisons this week. The number of independent evaluation surfaces is increasing faster than any vendor can track, creating accuracy-frame risk for unrepresented extractors.
  • OCR is being abstracted from a standalone API into a pluggable agent skill layer: modlens and agent-vision-toolkit both package OCR as callable skills for text-only coding agents, and DocSlicer ships an MCP server alongside its parser. This architectural shift may reduce demand for direct document-parsing API calls in developer workflows.
  • Open-source document parsing adoption at very large scale (50K+ stars) is concentrated in three tools—MinerU (77K), Docling (64K), OCRmyPDF (34K)—all actively maintained and zero-cost. These define the accuracy floor competitors and customers use to evaluate whether paid extraction APIs justify their cost.
  • VLM evaluation framework adoption is consolidating around lmms-eval and evalscope: both saw active pushes this week and cover overlapping benchmark sets (DocVQA, ChartQA, OmniDocBench). A two-framework consolidation means the evaluation surface competitors and researchers use to assess document VLMs is now more standardized and reproducible across labs.
