Patterns this build

  • Conference-backed VLM efficiency work is converging on Qwen-family models: GRACE (ICML 2026) compresses Qwen3-VL to INT4 via quantization-aware distillation; AgilePruner (ICLR 2026) prunes visual tokens to reduce inference cost and hallucination rates. Both papers target the same model family used in competing OCR systems, suggesting the accuracy-cost frontier for Qwen3-VL is being pushed down simultaneously from multiple research angles.
  • OCR-as-plugin for text-only agents is becoming an established pattern: dsh-vision-router and dsh-vision-toolkit (seen) both package OCR, layout, and grounding as discrete tool calls rather than native VLM vision. The pattern confirms developer preference for structured document-extraction API endpoints over general-purpose multimodal chat, which is the positioning Nanonets Agentic Data Extraction targets.
  • Rust is emerging as the implementation language of choice for performance-critical LLM serving and document infrastructure: PegaInfer (LLM inference), readur (OCR platform), and LMCache (KV cache) all use Rust as primary or core language, consistent with AnyDoc (Firecrawl, prior context) and LiteParse (run-llama). The Rust shift reduces runtime overhead in the pipeline layers surrounding document extraction APIs.
  • Hallucination is being framed as a calibration problem, not just a frequency problem: the VLM Brain MRI audit framework (ACM AI 2026) decomposes VLM failures into calibration error, abstention rate, and confident-wrong outputs. This multi-dimensional audit framing is distinct from binary hallucination rate measurement and may offer a sharper evaluation lens for document VLM failure modes like phantom rows and fabricated headers.
  • Developer tooling abstracts document and LLM provider APIs into single gateways: LiteLLM (56K stars) routes to 100+ providers including vision models behind an OpenAI-compatible interface. As gateway adoption grows, provider discoverability through the gateway becomes a customer acquisition factor; document-AI providers not natively listed in LiteLLM's registry face an additional evaluation step compared to those that are.
