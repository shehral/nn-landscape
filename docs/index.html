Patterns this build

  • MCP server integration is converging on baseline status for document extraction tools. Three items this build (Unstract, pdfmux, xberg) expose MCP servers for extraction workflows — indicating agent-native connectivity is shifting from a differentiator to a table-stakes integration pattern.
  • Output certification and cross-extractor auditing is emerging as a distinct product layer above parsing. pdfmux and opendataloader-bench together define an auditing framework where any extractor's output can be independently certified — a pattern that could become a procurement criterion.
  • The agentic document extraction API surface is commoditizing. LandingAI ADE-CLI, Unstract, and the OCR-3 endpoint design all converge on schema-based JSON extraction with similar CLI/API patterns — suggesting the design surface is becoming a commodity and differentiation will shift to model accuracy, latency, and cost.
  • Open-weight document parsing investment remains high, increasing supply-side pressure on API-only products. PaddleOCR (86K stars, #1 on OmniDocBench v1.6), Docling (64K stars, IBM watsonx GA), and new entrants like DocSlight and xberg collectively expand the open-weight offering customers can self-host.
  • The benchmark landscape for document parsing is expanding beyond OmniDocBench. ParseBench (agent-task success), opendataloader-bench (cross-extractor certification), and lmms-eval (multimodal harness) represent three distinct methodologies — absence of OCR-3 scores on any one of them now carries independent visibility cost.
